Bienvenido al lab

Entorno de pentesting web deliberadamente vulnerable para practicar las vulnerabilidades más comunes del OWASP Top 10.

Cada reto está conectado a una base de datos MySQL real. Los exploits funcionan de verdad.

🗄️ SQL Injection — Login Bypass
HIGH
La query se construye concatenando directamente el input del usuario sin sanitización ni prepared statements. La BD es MySQL real.
— Resultado —
🚩 FLAG{sqli_bypass_master} — Login bypassed con éxito
Prueba en el campo usuario:
admin' --  o  admin' OR '1'='1
La contraseña puede ser cualquier cosa.
-- Query ejecutada (MySQL real): SELECT * FROM users WHERE username = '[USER_INPUT]' AND password = '[PASS_INPUT]'; -- Con payload admin' -- SELECT * FROM users WHERE username = 'admin' --' AND password = '...'; -- El -- comenta el resto → siempre true
// VULNERABLE (Node.js) const q = `SELECT * FROM users WHERE username = '${username}' AND password = '${password}'`; db.query(q, callback); // FIX: Prepared statements db.query('SELECT * FROM users WHERE username = ? AND password = ?', [username, password], callback);

— Contenido del archivo —
🚩 FLAG{path_traversal_lfi_success} — Archivo del servidor leído
Prueba: ../../etc/passwd
o la flag escondida: ../../app/.env.secret
El servidor hace path.join('/app/public', name) sin validar que el resultado esté dentro del directorio.
// VULNERABLE: path.join resuelve '..' sin restricción const filePath = path.join('/app/public', name); fs.readFileSync(filePath, 'utf8'); // FIX: verificar que el path resuelto empieza con la base const base = path.resolve('/app/public'); const resolved = path.resolve(base, name); if (!resolved.startsWith(base + path.sep)) return res.status(403).send('Forbidden');

HIGH

http://localhost:3000/api/health — el propio backend
http://db:3306 — la base de datos MySQL
http://169.254.169.254/latest/meta-data/ — metadata AWS (si estuviese en cloud)
// VULNERABLE: hace request a cualquier URL sin validar app.post('/api/fetch', (req, res) => { const client = url.startsWith('https') ? https : http; client.get(url, response => { ... }); }); // FIX: whitelist de dominios permitidos const ALLOWED = ['api.trusted.com', 'cdn.trusted.com']; const parsed = new URL(url); if (!ALLOWED.includes(parsed.hostname)) return res.status(403).send('Forbidden');
🔐 JWT débil — Algorithm Confusion (alg:none)
HIGH
El servidor firma tokens con el secreto débil "secret" y acepta tokens con alg:none sin firma. Obtén un token como usuario normal y forgéalo con role:admin.
Paso 1 — Obtener token (usuario normal)

—
Paso 2 — Forjar token (alg:none + role:admin)
Token forjado
—
Paso 3 — Acceder al endpoint protegido
— Respuesta —
🚩 FLAG{jwt_alg_none_pwned} — Privilegios escalados sin conocer el secreto
Un JWT tiene 3 partes separadas por puntos: header.payload.signature
Si cambias el header a {"alg":"none"} y eliminas la firma, algunos servidores aceptan el token sin verificación.
El secreto débil "secret" también permite bruteforce con herramientas como hashcat.
// VULNERABLE: acepta alg:none sin firma if (header.alg === 'none') { decoded = JSON.parse(Buffer.from(parts[1], 'base64').toString()); // sin verificar firma — acepta cualquier payload } // FIX: algoritmos permitidos explícitos, sin 'none' jwt.verify(token, secret, { algorithms: ['HS256'] });
🚪 Broken Access Control — Endpoint admin expuesto
HIGH
El endpoint GET /api/admin/users verifica el rol del usuario leyendo el parámetro ?role= que viene del cliente. Cualquiera puede enviarlo.
— Respuesta —
🚩 FLAG{bac_admin_bypass} — Lista de usuarios + secretos filtrada
Cambia el rol a admin y envía la request. El servidor confía en el parámetro que tú controlas.

Fix: Verificar el rol desde la sesión del servidor, nunca desde el cliente.
// VULNERABLE: confía en el parámetro del cliente const role = req.query.role; if (role !== 'admin') return res.status(403).json({ error: 'Denegado' }); db.query('SELECT * FROM users', callback); // FIX: leer rol desde la sesión validada del servidor const role = req.session.user.role; if (role !== 'admin') return res.status(403).json({ error: 'Denegado' });

↩️ Open Redirect — Sin validación de destino
MED
El endpoint GET /api/redirect?url= redirige al usuario a cualquier URL sin verificar si es del dominio autorizado. Úsalo para phishing o bypass de políticas de origen.
— Respuesta del servidor —
🚩 FLAG{open_redirect_phishing} — Redirect a dominio externo confirmado
Cambia la URL a https://attacker.com/fake-login.
Un atacante enviaría el link https://tu-banco.com/api/redirect?url=https://attacker.com a sus víctimas — el dominio inicial parece legítimo.

Fix: Whitelist de dominios permitidos o solo redireccionar a rutas relativas.
// VULNERABLE: redirige a cualquier URL app.get('/api/redirect', (req, res) => { res.redirect(302, req.query.url); }); // FIX: solo rutas relativas del mismo dominio const url = req.query.url; if (!url.startsWith('/') || url.startsWith('//')) return res.status(400).send('URL inválida'); res.redirect(302, url);
☠️ Prototype Pollution — Contaminación de Object.prototype
MED
El endpoint POST /api/merge usa una función de deep merge que no filtra la clave __proto__. Al inyectar propiedades en el prototipo base, todos los objetos del proceso quedan afectados.
— Resultado —
🚩 FLAG{prototype_pollution_pwned} — Object.prototype contaminado
Envía exactamente: {"__proto__":{"polluted":"PWNED"}}
La función deepMerge llama a target["__proto__"] que devuelve Object.prototype, no una propiedad propia — así contamina el prototipo global.

Fix: Filtrar __proto__ y constructor en la función de merge.
// VULNERABLE: propaga __proto__ al prototipo base function deepMerge(target, source) { for (const key of Object.keys(source)) { if (typeof source[key] === 'object') { target[key] = target[key] || {}; deepMerge(target[key], source[key]); // target["__proto__"] = Object.prototype! } else { target[key] = source[key]; } } } // FIX: bloquear claves peligrosas if (key === '__proto__' || key === 'constructor' || key === 'prototype') continue;
📄 XXE — XML External Entity
MED
El endpoint POST /api/xml parsea XML del usuario y resuelve entidades externas del sistema (SYSTEM). Úsalo para leer archivos arbitrarios del servidor.
— Resultado —
🚩 FLAG{xxe_file_read_success} — Archivo del servidor leído vía XXE
La entidad SYSTEM "/ruta" le dice al parser que cargue el contenido de ese archivo.
Prueba con: /etc/passwd, /app/.env.secret, /proc/self/environ

Fix: Deshabilitar el procesamiento de DTDs y entidades externas en el parser.
// VULNERABLE: resuelve entidades SYSTEM del DTD const systemMatch = xmlInput.match(/SYSTEM\s+["']([^"']+)["']/); if (systemMatch) { const content = fs.readFileSync(systemMatch[1], 'utf8'); // lee el archivo! } // FIX: rechazar cualquier XML con DTD/entidades externas if (/DOCTYPE|ENTITY|SYSTEM|PUBLIC/i.test(xmlInput)) return res.status(400).send('DTD no permitido');
🧩 SSTI — Server-Side Template Injection (EJS)
CRIT
El endpoint POST /api/render renderiza con EJS el template que tú envías. Dentro del template puedes ejecutar JavaScript de Node.js, incluyendo comandos del sistema.
— Output renderizado —
🚩 FLAG{ssti_rce_via_ejs} — RCE conseguido vía template injection
En EJS, <%= expr %> evalúa y devuelve la expresión.
Prueba: <%= require('child_process').execSync('cat /etc/passwd').toString() %>
o: <%= process.env %>

Fix: Nunca renderizar templates controlados por el usuario. Usar solo templates del servidor.
// VULNERABLE: renderiza template del usuario app.post('/api/render', (req, res) => { const output = ejs.render(req.body.template, { user: 'guest' }); // RCE si template es malicioso res.json({ output }); }); // FIX: usar solo templates propios, nunca del usuario const output = ejs.renderFile('./templates/welcome.ejs', { user: sanitize(req.body.user) });
💀 Insecure Deserialization — RCE vía eval
CRIT
El endpoint POST /api/decode deserializa datos en base64 y ejecuta con eval() cualquier valor que empiece con _FUNC_:. Permite ejecución de código arbitrario.
— Resultado —
🚩 FLAG{insecure_deserialize_rce} — Código arbitrario ejecutado
El servidor deserializa JSON desde base64. Si un valor empieza con _FUNC_:, ejecuta el resto con eval().
Usa los botones para generar payloads pre-armados.

Fix: Nunca usar eval() en datos del usuario. Validar e identificar los objetos deserializados.
// VULNERABLE: eval() en valores del JSON const obj = JSON.parse(raw, (key, value) => { if (typeof value === 'string' && value.startsWith('_FUNC_:')) { return eval(value.slice(7)); // ejecución de código arbitrario } return value; }); // FIX: no usar eval, validar esquema estrictamente const obj = JSON.parse(raw); if (!obj.user || typeof obj.user !== 'string') throw new Error('Formato inválido');
