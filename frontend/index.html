Bienvenido al lab

Entorno de pentesting web deliberadamente vulnerable para practicar las vulnerabilidades más comunes del OWASP Top 10.

Cada reto está conectado a una base de datos MySQL real. Los exploits funcionan de verdad.

⚠ Este entorno es intencionalmente inseguro.
Úsalo solo en tu máquina local o red privada.
Nunca lo expongas a internet.
🗄️ SQL Injection — Login Bypass
HIGH
La query se construye concatenando directamente el input del usuario sin sanitización ni prepared statements. La BD es MySQL real.
— Resultado —
🚩 FLAG{sqli_bypass_master} — Login bypassed con éxito
Prueba en el campo usuario:
admin' --  o  admin' OR '1'='1
La contraseña puede ser cualquier cosa.
-- Query ejecutada (MySQL real): SELECT * FROM users WHERE username = '[USER_INPUT]' AND password = '[PASS_INPUT]'; -- Con payload admin' -- SELECT * FROM users WHERE username = 'admin' --' AND password = '...'; -- El -- comenta el resto → siempre true
// VULNERABLE (Node.js) const q = `SELECT * FROM users WHERE username = '${username}' AND password = '${password}'`; db.query(q, callback); // FIX: Prepared statements db.query('SELECT * FROM users WHERE username = ? AND password = ?', [username, password], callback);
💉 XSS Reflejado — Buscador
CRIT
El término de búsqueda se refleja en la respuesta sin escapado. El servidor devuelve el valor tal cual desde /api/search?q=
— Resultado —
🚩 FLAG{xss_reflected_pwned} — XSS ejecutado en el DOM
Prueba: <script>alert(1)</script>
o: <img src=x onerror=alert(document.cookie)>
// VULNERABLE: refleja sin escapar app.get('/api/search', (req, res) => { res.json({ query: req.query.q }); // sin sanitizar }); // FIX: const escapeHtml = s => s.replace(/[&<>"']/g, c => ({'&':'&','<':'<','>':'>','"':'"',"'":'''}[c]));
🔑 IDOR — Acceso a perfiles
MED
Estás autenticado como usuario #5. La API GET /api/user?id= no verifica ownership. Accede al perfil del admin (ID 1).
— Respuesta JSON —
🚩 FLAG{idor_admin_exposed} — Datos del admin filtrados
Cambia el ID a 1. El campo secret del admin contiene la flag.
// VULNERABLE: sin verificar ownership app.get('/api/user', (req, res) => { const id = req.query.id; db.query('SELECT * FROM users WHERE id = ?', [id], callback); }); // FIX: verificar que id == sesión del usuario if (id != req.session.userId && !req.session.isAdmin) return res.status(403).json({ error: 'Forbidden' });
💾 XSS Almacenado — Foro
CRIT
Los mensajes se guardan en MySQL y se sirven sin escapar. Cualquier usuario que cargue el foro ejecutará tu payload.
🚩 FLAG{stored_xss_persisted} — Payload almacenado en BD
Publica: <img src=x onerror="alert('XSS')">
Luego haz clic en "Actualizar" para ver el payload persistido en la BD.

🎭 CSRF — Cambio de email
MED
El endpoint POST /api/change-email no valida ningún token CSRF. Simula que la víctima (user_id=5) visita una página maliciosa.
Email actual de la víctima
Cargando...
Página maliciosa del atacante
— Resultado —
🚩 FLAG{csrf_no_token_pwned} — Email cambiado sin consentimiento
Solo haz clic en el botón. En un ataque real, la víctima ni siquiera lo nota: la request se dispara al cargar la página maliciosa.

Fix: Incluir un CSRF token único por sesión y validarlo en el servidor.
// VULNERABLE: sin token app.post('/api/change-email', (req, res) => { db.query('UPDATE emails SET email = ? WHERE user_id = ?', [email, user_id], cb); }); // FIX: generar y validar CSRF token if (req.body.csrf_token !== req.session.csrf_token) return res.status(403).send('Forbidden');
